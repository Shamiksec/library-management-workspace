Library Management System

A MySQL database that tracks books, physical copies, members, loans, reservations and fines. Built for our DBMS project by Group G2.

Entity-relationship diagram

Books and their physical copies are separate, so one title can have many copies and each loan points to one specific copy.

The nine tables

Every table matches the SQL script.

authors

Author name, nationality and birth date.

publishers

Publisher name (unique), city and phone.

categories

Subject categories such as Fiction or Database Systems.

books

One row per title: ISBN, publisher, category, year, edition, language.

book_authors

Links books to authors, so a book can have many authors and the reverse.

book_copies

Each physical copy with accession number, shelf and status (available, issued, lost, damaged, withdrawn).

members

Library members with unique email and status (active, suspended, closed).

loans

Issue, due and return dates for a copy borrowed by a member.

reservations

A waiting queue for titles with no copy free.

fines

At most one fine per loan, with amount, reason and payment status.

Rules the database enforces

  • A copy can have only one active loan at a time. A generated column plus a unique key blocks double-issuing.
  • A due date can never be earlier than the issue date.
  • Fine amounts cannot be negative, and each loan has at most one fine.
  • Books, copies, members and loans cannot be deleted while other records depend on them. Deleting a book also removes its author links.
  • Emails, ISBNs and accession numbers must be unique.

Sample queries

Open one to read it. The full set of 12 is in the SQL script.

Available copies by title 
SELECT b.title,
       SUM(CASE WHEN bc.copy_status = 'AVAILABLE' THEN 1 ELSE 0 END) AS available_copies,
       COUNT(bc.copy_id) AS total_copies
FROM books b
LEFT JOIN book_copies bc ON bc.book_id = b.book_id
GROUP BY b.book_id, b.title
ORDER BY b.title;
Overdue loans as of today 
SELECT l.loan_id, m.full_name, b.title, l.due_date,
       DATEDIFF(CURRENT_DATE, l.due_date) AS days_overdue
FROM loans l
JOIN members m ON m.member_id = l.member_id
JOIN book_copies bc ON bc.copy_id = l.copy_id
JOIN books b ON b.book_id = bc.book_id
WHERE l.return_date IS NULL AND l.due_date < CURRENT_DATE;
Unpaid fines 
SELECT f.fine_id, m.full_name, b.title, f.amount, f.reason
FROM fines f
JOIN loans l ON l.loan_id = f.loan_id
JOIN members m ON m.member_id = l.member_id
JOIN book_copies bc ON bc.copy_id = l.copy_id
JOIN books b ON b.book_id = bc.book_id
WHERE f.payment_status = 'UNPAID';
Issue a book (transaction) 
START TRANSACTION;
SELECT copy_status FROM book_copies WHERE copy_id=1 FOR UPDATE;
INSERT INTO loans (copy_id,member_id,issue_date,due_date,loan_status,issued_by)
VALUES (1,3,CURRENT_DATE,DATE_ADD(CURRENT_DATE, INTERVAL 14 DAY),'ISSUED','Librarian');
UPDATE book_copies SET copy_status='ISSUED'
WHERE copy_id=1 AND copy_status='AVAILABLE';
COMMIT;
Members who have never borrowed 
SELECT m.member_id, m.full_name
FROM members m
LEFT JOIN loans l ON l.member_id = m.member_id
WHERE l.loan_id IS NULL;

Run it on your computer

This is a database project, so it runs in MySQL rather than in the browser.

  1. Install MySQL Server 8.0 or newer and MySQL Workbench.
  2. Download library_management_system.sql and open it in Workbench.
  3. Run the whole script. It drops and recreates a database named library_management_system, so don't run it where that name holds data you need.
  4. Refresh SCHEMAS and expand the new database to see the tables.
  5. Run the report queries one at a time. Sample data is fictional.
